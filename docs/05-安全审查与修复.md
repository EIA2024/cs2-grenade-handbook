# 05 · 安全审查与修复

审查范围：整个当前项目源码、权限清单、构建和打包脚本；以 1.1.0 行为与本次用户要求为基准。工作区没有 Git 历史，因此没有把本次审查描述为某个提交差异审查。修复版本 1.1.1，完成日期 2026-09-23。

结论：发现并修复文件安全、损坏数据恢复、输入生命周期和交付内容方面的问题。未发现游戏访问、注入、全局输入钩子、输入模拟或游戏窗口控制实现。后一句仅是所审源码范围内的技术结论，不能预测 VAC 对任意环境或未来版本的判定。

## Standards：安全及工程边界

| 编号/级别 | 原问题与触发方式 | 修复与证据 |
| --- | --- | --- |
| S1 / P1 | 构造仓库会直接覆写固定 .write-test；已有文件被破坏，预置链接可能写向库外 | 随机名称 + CreateNew；测试预置同名文件仍保持原文 |

| S4 / P2 | ZIP 容许任意附件，用户打开资料文件夹后可能接触可执行文件或 Shell 快捷方式 | 只接受约定双图及说明；不执行任何附件。测试拒绝 .exe 和非法编码；不是原先存在自动远程代码执行 |

P1 表示有实际文件数据/授权边界影响，不表示提权到管理员；利用预置链接的场景需要能够改写本软件数据目录。P2 表示可用性、数据一致性或分发风险。

## Spec：原需求正确性

| 编号/级别 | 原问题与触发方式 | 修复与证据 |
| --- | --- | --- |

## 权限与 VAC 结论

- 清单为 asInvoker、uiAccess=false；不申请管理员权限、驱动、后台服务或进程调试权限。用户手动以管理员启动时仍会继承该令牌，清单不是沙箱。
- 直接原生入口只有本软件窗口的 GetWindowLongPtrW、SetWindowLongPtrW、SetWindowPos，以及 RegisterRawInputDevices、GetRawInputData。
- Raw Input 使用 RIDEV_INPUTSINK，仅消费绑定键和修饰状态；不拦截、不转发、不模拟输入、不处理鼠标位移。隐藏不注销是既定使用模式，返回编辑器/鼠标调整或退出会注销。
- 普通置顶面板及 Raw Input 是需要说明的系统集成能力，并非已发现的作弊代码，也不能仅因采用 Windows 官方 API 就宣称 VAC 安全。
- 对局中需要人类看图、自行移动和投掷，没有自动游戏动作。快捷菜单始终不激活自身窗口；编辑器和显式调整只激活自身窗口。

Valve 的协议第4节禁止作弊、未经授权的干预和自动化，并保留自动检测与人工执行权；它不是对本软件的许可或免责。2026-09-22/23 核查：[Steam Subscriber Agreement，第4节](https://store.steampowered.com/subscriber_agreement/#4)。本次未找到对“普通置顶窗口 + Raw Input 图片手册”的逐项豁免，不能给出封禁概率或“绝不封禁”保证。[VAC 官方帮助](https://help.steampowered.com/zh-cn/faqs/view/571A-97DA-70E9-FF74)可供进一步核对，但公开帮助不是本项目认证。

## 已验证与仍有限制

自动测试及发布验证见“04-本次验收记录”。测试只读写项目测试资料、操作本软件窗口；未查询、启动或读取 CS2。边界脚本只是可重复的静态检查，不能证明所有未来代码或运行时依赖都安全。

仍需用户真实键鼠验证前台双响应、实际穿透、CS2本地练习可见性、不同显示模式、DPI和帧率。注册/注销失败路径已审代码，未通过驱动或故障注入制造真实OS失败。

剩余威胁模型限制：没有对恶意同用户并发替换目录实施内核级隔离，未识别所有硬链接；程序文件/运行时由可写目录加载，无法抵御有能力篡改整套程序和哈希清单的攻击者；图片使用系统解码器，未进行二进制模糊测试或系统补丁审计。大库扫描虽有预算，仍同步执行，不保证瞬时完成。

优化保持独立桌面软件边界，未增加游戏识别、插件执行、输入补偿或更高权限。模块和扩展入口见“06-开发者架构”。
